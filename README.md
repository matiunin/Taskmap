# Taskmap — самостоятельное развёртывание

Taskmap показывает задачи Jira и их связи в виде интерактивной карты. Можно
загружать задачи, просматривать описание, менять связи, отменять локальные
правки и применять подготовленные изменения в Jira.

Эта версия работает с вашим Jira и вашим сервером. Все функции доступны без
подписки и оплаты; предусмотрена необязательная разовая поддержка автора
через Robokassa. Внешнего сервиса обратной связи, базы пользователей и
операторской автоматизации нет. Лицензия — [MIT](LICENSE); условия сторонних ресурсов —
[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Быстрый запуск через Docker

Нужны Docker Engine с Compose либо Docker Desktop и доступ к Jira Cloud.
Клонируйте репозиторий или распакуйте архив, затем откройте папку проекта.

```sh
cp .env.example .env
```

В `.env` замените пример на домен своего Jira:

```dotenv
TASKMAP_JIRA_HOSTS=example.atlassian.net
```

Указывайте точные имена хостов без протокола и пути. Для нескольких Jira
перечислите их через запятую. Это список разрешённых адресов для сервера;
не добавляйте чужие хосты и не используйте `*`.

```sh
docker compose up --build -d
docker compose ps
curl --fail http://127.0.0.1:8080/api/health
```

Откройте **http://127.0.0.1:8080**. Введите адрес своего Jira, email и API
token Jira. Затем загрузите тестовую задачу и откройте карту.

По умолчанию порт доступен только с компьютера, где запущен Docker.
Контейнеру нужны DNS и исходящий HTTPS-доступ к разрешённому Jira.

Остановка:

```sh
docker compose down
```

## Подключение Jira

1. Войдите в аккаунт Atlassian, которому доступны нужные проекты Jira.
2. Откройте [управление API-токенами аккаунта](https://id.atlassian.com/manage-profile/security/api-tokens).
3. Выберите **Create API token** — обычный токен без scopes. Задайте имя
   и срок действия, создайте токен и скопируйте выданное значение.
4. В форме Taskmap укажите адрес Jira Cloud, почту этого же аккаунта и токен.
   Загрузите задачу, доступную аккаунту, чтобы проверить подключение.

Права на просмотр и изменение задач определяет Jira. Сам токен не добавляйте
в `.env`, исходники или опубликованные примеры: его вводят в интерфейсе.

Текущая версия обращается к API через адрес вашего Jira Cloud. Токены
**with scopes**, которым нужен маршрут `api.atlassian.com/ex/jira/...`,
здесь не поддерживаются. Различия описаны в
[инструкции Atlassian](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account).

## Развёртывание на сервере

1. Установите Docker с Compose и перенесите исходники приложения.
2. Создайте `.env` из примера и задайте свои `TASKMAP_JIRA_HOSTS`.
3. Настройте HTTPS reverse proxy на `127.0.0.1:8080` и передавайте заголовок
   `Host`. Приложение рассчитано на размещение в корне отдельного домена.
4. Укажите точный внешний origin, например:

   ```dotenv
   TASKMAP_PUBLIC_ORIGIN=https://taskmap.example.com
   ```

5. Запустите `docker compose up --build -d` и проверьте `/api/health`.

Для закрытой командной установки ограничьте доступ на reverse proxy
аутентификацией или сетью команды. Пользовательские Jira credentials
вводятся в приложении; сервер не содержит общего Jira token.

Настройка Apache, PHP и ограничения прокси уже включены в образ. MySQL,
SMTP и сторонний бот не нужны. Платёжный аккаунт требуется только при
включении добровольной поддержки автора.
Веб-каталог содержит только собранный интерфейс и необходимые API-обработчики;
серверная конфигурация и основной PHP-код находятся вне веб-каталога.

## Локальная разработка

Нужен **Node.js 24** с npm. Версия указана в `.nvmrc`. Docker для этого
режима не требуется; PHP нужен для отдельной проверки production backend.

```sh
npm ci
cp .env.example .env
```

Заполните `TASKMAP_JIRA_HOSTS`, затем:

```sh
npm run dev:with-proxy
```

Откройте **http://127.0.0.1:3000**. Vite передаёт Jira-запросы локальному
Node-прокси на `127.0.0.1:3004`; оба процесса останавливаются вместе.

Для другого локального имени задайте `DEV_ALLOWED_HOSTS` и, при
необходимости, `DEV_HOST`. Не открывайте сервер разработки в интернет.

```sh
npm run build
```

Результат — `dist/`. `npm run preview` позволяет посмотреть интерфейс,
но не запускает PHP/API. Для полной production-проверки используйте Docker.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `TASKMAP_JIRA_HOSTS` | Точный список разрешённых Jira-хостов; пустое значение блокирует исходящие запросы. |
| `TASKMAP_PUBLIC_ORIGIN` | Внешний origin при HTTPS reverse proxy; без пути и завершающего `/`. |
| `TASKMAP_PROXY_PORT` | Порт Node-прокси для разработки; адрес всегда loopback. |
| `DEV_HOST`, `DEV_ALLOWED_HOSTS` | Адрес и допустимые имена Vite для разработки. |
| `VITE_JIRA_PROXY_URL` | Необязательный путь API на том же origin для локальной npm-сборки интерфейса. |
| `TASKMAP_DONATIONS_ENABLED` | Runtime сервера: включает добровольные донаты; по умолчанию `false`. |
| `TASKMAP_ROBOKASSA_MERCHANT_LOGIN` | Runtime сервера: идентификатор отдельного магазина Robokassa для донатов. |
| `TASKMAP_ROBOKASSA_PASSWORD1`, `TASKMAP_ROBOKASSA_PASSWORD2` | Только runtime сервера: технические пароли выбранного магазина и режима. |
| `TASKMAP_ROBOKASSA_TEST_MODE` | Runtime сервера: по умолчанию `true`; использует тестовую пару паролей. |
| `TASKMAP_ROBOKASSA_HASH_ALGORITHM` | Runtime сервера: `md5`, `sha256` или `sha512`, как в настройках магазина. |
| `TASKMAP_DONATION_DATA_DIR` | Необязательный каталог учёта донатов: Docker `/var/lib/taskmap/donations`, Node `data/donations`. |

`TASKMAP_*` — серверные значения из runtime-окружения. `.env` остаётся на
машине развёртывания и не копируется в builder или веб-каталог. Любая `VITE_*` переменная попадает в
интерфейс: **не помещайте туда токены, пароли или приватные ключи**.
`VITE_JIRA_PROXY_URL` из `.env` используется при локальном `npm run build`.
Docker использует стандартные маршруты API на том же origin и не передаёт
этот override в builder. Стандартные маршруты выбираются по режиму сборки,
поэтому свой домен не требует изменений в исходниках.

Поддерживаемый сценарий — Jira Cloud API v3. Права на просмотр и изменение
задач определяет Jira. Automation требует отдельных прав Jira и может быть
недоступна в некоторых тарифах или организациях. Jira Server/Data Center и
Jira в частной сети не заявлены как проверенный вариант этой установки.

## Добровольная поддержка автора

При включённой настройке интерфейс предлагает три **разовых** доната через
Robokassa: **490, 2 490 и 3 990 ₽**. Это добровольная поддержка без подписки,
автосписаний и ограничений доступа. Неоплата или отказ не меняют работу
приложения. По умолчанию донаты выключены; при неполной конфигурации кнопки
не показываются.

Автоматическое предложение появляется с третьего визита, в котором Jira
успешно вернул данные. Визит — отдельная вкладка или новая вкладочная сессия:
перезагрузка страницы, повторное подключение и сохранение настроек не
увеличивают счётчик. Окно ждёт примерно 15 секунд спокойной работы в видимой
вкладке и откладывается при загрузке, настройках, других диалогах или
неприменённых изменениях. Перед подключением и при ошибке Jira оно не
открывается. Кнопки поддержки внизу страницы и в настройках доступны вручную.
После первого реального открытия любым способом автоматических напоминаний
больше нет. Браузер хранит только счётчик до трёх и флаг показа; при недоступном
хранилище автоматическое предложение отключается.

Для донатов выделите **отдельный магазин внутри своего аккаунта Robokassa**.
Не меняйте настройки магазина, который уже обрабатывает другие платежи
или права доступа. В технических настройках нового магазина укажите свои
HTTPS-адреса и методы:

| Настройка магазина | Адрес | Метод |
| --- | --- | --- |
| `ResultURL` | `https://taskmap.example.com/api/donation-result.php` | `POST` |
| `SuccessURL` | `https://taskmap.example.com/?donation=returned` | `GET` |
| `FailURL` | `https://taskmap.example.com/?donation=cancelled` | `GET` |

Замените домен на адрес своей установки. Возврат в браузер не подтверждает
оплату: статус счёта меняется только после проверенного серверного уведомления.
См. [уведомления Robokassa](https://docs.robokassa.ru/ru/notifications-and-redirects).

В локальной `.env` задайте `TASKMAP_PUBLIC_ORIGIN`, включите
`TASKMAP_DONATIONS_ENABLED=true` и заполните merchant login и оба технических
пароля. Начните с `TASKMAP_ROBOKASSA_TEST_MODE=true`: используйте именно
тестовую пару паролей и совпадающий алгоритм хэширования. Боевые пароли
не подставляются вместо отсутствующих тестовых. Правила подписи описаны в
[интерфейсе оплаты Robokassa](https://docs.robokassa.ru/ru/pay-interface).
После проверки тестового режима переход на боевой требует соответствующей
пары паролей и `TASKMAP_ROBOKASSA_TEST_MODE=false`.

```sh
docker compose up -d --build
```

Для Node-разработки перезапустите `npm run dev:with-proxy`. Настройки донатов
читаются сервером при запуске и **не являются `VITE_*` или build args**;
пароли никогда не должны попадать в сборку интерфейса.

Приложение передаёт в создание доната только выбранный вариант и язык.
Email, token и содержимое Jira не отправляются в Robokassa. Учёт хранит
только номер счёта, вариант, сумму, время создания/оплаты и режим. В Docker
он сохраняется в отдельном named volume; не удаляйте его при обновлениях,
если есть незавершённые оплаты. MySQL и база пользователей не нужны.

## Данные и credentials

API token передаётся вашему серверу только для выполнения Jira-запроса,
затем сервер обращается к вашему Jira по HTTPS. На публичном сервере
обязательно используйте HTTPS для браузера.

Настройки подключения хранятся в `sessionStorage` вкладки. Применяемая
кодировка не является шифрованием. Загруженные задачи и настройки интерфейса
могут сохраняться локально в браузере. Действие «Отключиться» удаляет
данные подключения, кэш загруженных задач, историю задач и сохранённые
цвета задач. Язык, настройки интерфейса, счётчик визитов и отметка показа
донат-окна сохраняются.

Сервер не записывает Jira credentials или содержимое задач в свою базу.
Собственные логи reverse proxy также не должны сохранять тела запросов.
Подробнее: [SECURITY.md](SECURITY.md).

## Обновление и резервная копия

Сохраните свою `.env` и настройки reverse proxy отдельно от репозитория.
Если включены донаты, также сохраните резервную копию named volume
`donations` с учётом счетов. При обновлении и откате сохраняйте этот volume;
`docker compose down -v` удаляет его. Для согласованной копии остановите
контейнер на время резервного копирования.
При наличии важных локальных правок карты сначала примените их в Jira:
серверной базы пользовательских задач нет.

Обновите исходники из выбранного вами репозитория и выполните:

```sh
docker compose up --build -d
docker compose ps
curl --fail http://127.0.0.1:8080/api/health
```

Для отката используйте прежнюю версию исходников и повторно соберите образ.
Изменения серверных настроек в `.env` требуют пересоздания контейнера.
Изменения `VITE_*` для локальной npm-сборки требуют нового `npm run build`;
Docker продолжает использовать стандартные маршруты API.

## Проверки перед изменениями и публикацией

```sh
npm ci
npm run check
npm audit
```

`npm run check` собирает интерфейс, запускает тесты Node/PHP прокси,
проверяет PHP-синтаксис и состав публичных файлов. Для этих проверок нужны
Node.js 24 и PHP 8.4+ с cURL. Тесты используют синтетические данные и не
обращаются к реальному Jira. Тесты донатов охватывают подпись, сумму,
режим и повторные уведомления на синтетических данных без реальных платежей.

Проверка состава файлов — дополнительная защита. Перед публикацией также
просмотрите staged-файлы и историю и запустите отдельный secret scanner.
Не добавляйте `.env`, credentials, пользовательские выгрузки и рабочие
скриншоты. Историю другого репозитория и его `.git` копировать не нужно.

## Если что-то не работает

| Симптом | Проверка |
| --- | --- |
| `503`, Jira-хост не настроен | Задайте `TASKMAP_JIRA_HOSTS` и пересоздайте контейнер / перезапустите Node-прокси. |
| `403`, хост не разрешён | Адрес в форме должен точно совпасть с разрешённым hostname. |
| `403`, origin не совпадает | Проверьте `TASKMAP_PUBLIC_ORIGIN`, внешний HTTPS-адрес и `Host` у reverse proxy. |
| `401` от Jira | Проверьте email, API token и его действительность. |
| `403` от Jira | Проверьте права пользователя на проект, задачи и Automation. |
| Ошибка DNS / timeout | Проверьте исходящий HTTPS, DNS и доступность Jira. Частные/reserved IP намеренно блокируются. |
| `/api/health` работает, но в preview нет задач | `npm run preview` не включает backend; используйте dev с Node-прокси или Docker. |
| Сборка не запускается | Проверьте Node.js 24, выполните `npm ci`, затем `npm run build`. |
| `409` при уведомлении о донате после сбоя | Остановите экземпляр и убедитесь, что запись счёта больше не выполняется. Удалите только оставшийся файл `<номер>.json.lock` в каталоге донатов, сохраните `<номер>.json` и запустите экземпляр, чтобы принять повторное уведомление Robokassa. |

Структура и назначение исходников описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
